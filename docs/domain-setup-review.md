# Customer domain interface review

Feature 7b step 5 is implemented locally. This checklist is **not completed browser evidence**. No browser runner is configured. Use an isolated local/test site with test billing and fake DNS/provider responses for the states below. Leave production rollout flags closed. The corresponding owner-state fixtures live in `tests/Feature/SiteDomainSummaryTest.php`; action fixtures are in the domain and billing feature tests.

Open Dashboard → the site's Settings → Go Live, beside the site name. Custom domain and Billing share equal-width columns on large screens and stack on smaller screens. The Site settings link returns to the editor. With rollout disabled, the panel explains that setup is unavailable and offers no connection actions. Enabled local setup requires `customer-domains.enabled`; unpaid checkout also requires `site-billing.checkout_enabled` and test billing configuration. Do not enable production checkout for this review.

| State              | Expected review result                                                                                                                                                                            |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Empty              | Labeled full www input, example, monthly/yearly choices, payment-before-DNS disclosure, no trial.                                                                                                 |
| Submitting         | Request feedback and disabled submit/actions; rapid clicks cannot submit twice. Navigation is protected while the request runs.                                                                   |
| Invalid            | Submit a bare hostname or a URL. A field-associated error appears and focus returns to the hostname. No checkout begins.                                                                          |
| Unavailable        | A fake provider failure produces safe text, retained settings, and retry. An uncertain create explains support review; no raw provider data appears.                                              |
| Checkout canceled  | Return with `?billing=canceled`. The saved domain/plan remains resumable; the URL never grants paid access.                                                                                       |
| Payment processing | Return with `?billing=processing` before payment confirmation. Payment stays pending; a confirmed server update changes progress. No second subscription is offered once one exists.              |
| DNS pending        | Separate TXT ownership and CNAME instructions appear. Copy each name/value; hear/read copy feedback. Wrong TXT or CNAME cannot show live.                                                         |
| SSL pending        | With DNS/connection confirmed and certificate pending, HTTPS remains pending separately.                                                                                                          |
| Unpublished        | With paid access and connection ready, publishing is still required.                                                                                                                              |
| Live               | With all requirements met, “Your domain is live” appears. Scheduled checks continue without browser polling.                                                                                      |
| Unpaid retained    | After paid access expires, saved records remain visible but custom-domain access is unavailable. Billing management or eligible checkout is separate.                                             |
| Removal pending    | Cancel the confirmation first: no change. Confirm it: old-host serving stops, replacement is unavailable until cleanup completes, and billing continues. The Cancel renewal link reaches Billing. |

Review at narrow and wide widths, using keyboard only as well as pointer. Verify heading/error focus after requests, readable long DNS values, no horizontal page overflow, copy failure feedback when clipboard access is unavailable, and text-only rendering of all server values. Tab to the cancellation link and confirm its target can receive focus. Check that an unsaved hostname pauses polling and prompts before leaving Go Live. Unsaved Settings edits must still prompt before opening Go Live; submitting the domain itself should not ask to discard its own hostname.

While setup is pending and the document is visible, status-only reloads occur every 20 seconds for at most 30 attempts. They pause during edits/requests, stop for settled or support-blocked states, and never initiate provisioning themselves. Refresh/retry performs an owner-scoped check. The scheduler handles provisioning every five minutes when enabled. Inspect browser network activity to confirm these behaviors and absence of unexpected repeated checkout requests.

Record observed state, viewport/browser, focus/copy results, and any failures before marking step 5's manual review complete. Real DNS, TLS, provider permissions, and Stripe payment evidence belong to the separately approved controlled rollout in the operations runbook.

For the authorized local sandbox walkthrough, set `CUSTOMER_DOMAINS_LOCAL_TESTING=true` in the ignored local `.env`. Both gates require `APP_ENV=local` or `APP_ENV=staging` and a `sk_test_` key. On staging, save the same explicit flag in its own environment after deploying the updated configuration. Remove the testing flag when finished. This does not enable production or deploy Worker routing. The existing proof hostname and its descendants are reserved; use a separate operator-owned `www` hostname.
